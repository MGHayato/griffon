オンライン対戦とGoogle Play配信までの道のり

CPU対戦のWebゲームから、ゲームの充実、友達とのオンライン対戦、 そしてGoogle Playでの配信へ。全部を一度にやると必ず作り直しが出るので、 順番に意味がある形で並べた。

いまここ
  • スマホアプリとして遊べる ── mghayato.github.io/griffon/
  • ホーム画面に追加すると 全画面・縦固定で起動。電波がなくても動く
  • git push するだけで テスト → ビルド → 公開まで自動で走る
  • カード20種40枚。マニュアル、カード拡大表示、手札のコスト順ならべ替えも入った
  • ルールの読み取りは core/ に分離ずみ。テスト26件が守っている
つぎの一手
  • フェーズ3：ゲームを充実させる（デッキ／リーダーキャラ／プレイヤーネーム）
  • 対人戦の前に ここをやると決めた。対戦相手ができてから中身を変えると 調整が二重になるため

5つのフェーズ

土台を分ける

半分おわった 費用なし
目安：あとセッション2〜3回／フェーズ4の直前でよい

もう終わったこと

  • Gitを入れて、いつでも巻き戻せるようにした
  • 1ファイル2200行 → Viteで分割開発・ビルドで1ファイル出力
  • カード定義・状態・盤面の読み取りを core/ へ切り出し
  • テスト26件（ガード・ブロック・手札のならべ替え）

残っていること

  • ルールの中から 画面の呼び出しを引き剥がす（dealDamage が画面を揺らしている、など）
  • プレイヤーの操作を「命令」として表現する（例：2列目の前に召喚 というデータ）
終わると：見た目も遊び心地も何も変わらない。 でもルールがサーバーでも動くようになり、オンライン対戦の前提が揃う。
なぜ必要か：対人戦は「2人の画面で 同じルールが 同じ結果になる」ことが大前提。 いまはルールの計算と画面の描き換えが混ざっているので、サーバー側で同じ計算ができない。
いつやるか：フェーズ3でカードやリーダーを足すと、その分も引き剥がす対象になる。 だからフェーズ3が済んでから、フェーズ4の直前にまとめてやるのが手戻りが少ない。

ゲームを充実させる

つぎはここ 費用なし
目安：セッション4〜8回（作りたい量しだい）

やること

  • プレイヤーネーム ── 名前を決められるようにする
  • カードを増やす ── いまの20種では デッキを分けても 中身がほぼ同じになる
  • デッキを増やす ── プリセットから選べるようにする
  • リーダーキャラ ── デッキごとに 専用のリーダーを作る
終わると：「毎回おなじ40枚」から抜け出して、選ぶ楽しみが生まれる。 対人戦がぐっと面白くなる。
なぜ対人戦より先か：対戦を先に作ると、カードを1枚足すたびに 対戦の動作も確かめる必要が出てくる。中身を固めてから対戦に進むほうが早い。
順番の目安：プレイヤーネームは小さく独立していて、対人戦の下ごしらえにもなる。 カードを増やすのが先、デッキ分けはその後（材料が足りないとデッキの個性が出ない）。 リーダーキャラはデッキ選択画面とセットになるので いちばん最後。

お金：無料枠から始められる。友達数人なら当分ずっと0円のはず。

Google Play で配信

約4,000円＋テスター12人
目安：準備セッション2〜3回＋テスト期間14日＋審査7日

やること

  • Capacitor でアプリの殻をかぶせる（中身はフェーズ2のまま使える）
  • スクリーンショット、説明文、プライバシーポリシーを用意
  • Google Play Console に登録（初回のみ 約4,000円）
  • クローズドテスト：12人以上 × 14日連続
  • 公開申請 → 審査（通常7日以内）
終わると：ストアからインストールできる。GOAL 2 達成。
ビルド環境はもう揃っている：Android Studio と Android SDK が このPCに入っていることを確認ずみ。Windowsだけで完結する（Macは要らない）。
本当の関門はテスターの方：下で詳しく説明する。

最大の関門：テスター12人 × 14日

2023年11月13日以降に作った個人のデベロッパーアカウントは、 アプリを公開する前にこの条件を満たす必要がある。 満たさないと公開申請そのものができない。

条件中身
人数12人以上
期間14日間 連続
途中で抜けたらその人のカウントはリセット。再参加しても14日やり直し
対象2023年11月13日以降に作った個人アカウント
対象外法人アカウント／それ以前に作った個人アカウント

当初は20人だったが、2026年7月29日から12人に緩和された。 それでも「12人に14日間インストールしたままにしてもらう」のは楽ではない。

すでにPWAとして配れる状態にはなっているので、 「14日入れっぱなしにして」と頼む前に、リンク1つで遊んでもらって 面白いと思ってもらうことができる。フェーズ3で中身を厚くしておくほど、頼みやすくなるはず。

アプリにする方法の選び方

フェーズ5で Capacitor を選んだ理由は、いまのコードがそのまま中身になるから。

方法いまのコード学習コスト向いているもの
Capacitor そのまま使える ほぼゼロ Webで作ったものをアプリにする
React Native見た目は作り直し中〜大ネイティブの操作感が要るアプリ
Flutter全部作り直し大凝ったUIを両OSで完全に揃えたい
Unity全部作り直し大3Dや重い演出のゲーム

React Native には HTML も CSS も無い。盤面のマス、カードのめくれ、稲妻のSVG ── 見た目はぜんぶ作り直しになる。グリフォンは絵文字とCSSで動く2Dカードゲームなので、 WebViewの速度で困る場面はまず来ない。

  • デッキビルダー（プリセットが回ってからでいい）
  • スマホでの拡大表示を もう少し大きくする（保留中）
  • 課金やアイテム、商標登録、サーバー増強

この計画は決定事項じゃなくて、順番の提案。 途中で面白い脱線が見つかったらそっちを優先していい。 ただし フェーズ1（土台を分ける）は、オンライン対戦をやるなら必ず通る。 フェーズ3でカードを足すほど作業も増えるので、フェーズ4の直前にまとめてやる想定にしてある。
